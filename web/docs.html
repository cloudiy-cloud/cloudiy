Introduction

The Internet connected computers. Blockchain connected value. AI connected intelligence. What was still missing is an open protocol connecting compute. Cloudiy is that protocol: any identity can provide computational resources, and any identity can consume them, through one universal API.

Cloudiy is not a cloud provider, not a marketplace, not a GPU rental platform. Users never think about Docker, VMs, GPU drivers, CUDA installs, networking or servers — those are implementation details. You describe what you need; the protocol decides how it runs.

  • • Everything is a Resource — CPU, memory, GPU, VRAM, storage, bandwidth, and future hardware, without redesign.
  • • Everything is an Identity — human, AI agent, company, DAO or another protocol: indistinguishable by design.
  • • Capabilities are first-class — request cuda:12.8 and pytorch, never "machine X".
  • • The unit of execution is the Workload — declared, scheduled, isolated, measured, destroyed. Resources return automatically.

Protocol on Solana

Blockchain is an implementation detail, kept behind interfaces. Today's settlement modules:

  • • x402 payment quotes (price in USDC per workload, no accounts, no API keys)
  • • USDC payment escrow (Anchor, live on devnet)
  • • Signed results — ed25519 proof of which node computed what
  • • Future: streaming payments, on-chain reputation, proof of compute

USDC Escrow

All payments are locked in an escrow on Solana. The provider only receives funds after successful job completion (or after timeout/dispute).

  • 1. Consumer rents a GPU — USDC is locked in the escrow program (Anchor).
  • 2. Provider executes the job and submits the signed result.
  • 3. On confirmation, the escrow releases USDC to the provider, minus protocol fee.
  • 4. On timeout or dispute, funds return to the consumer.

The escrow program (Anchor) is live on devnet: 9zMBC7JDA8SJ2mk3ATYqRuJvn14MQyZVg9q3XPnzc1TN — instructions create_job, release and refund, with a 4% protocol fee. Pricing is quoted over HTTP via the x402 protocol: nodes respond 402 Payment Required with the USDC price and clients retry with an X-PAYMENT header — no accounts, no API keys.

Providers

Providers don't rent computers — they contribute resources. Install the node, and it discovers your hardware automatically. You choose the slice to share; the rest stays private:

$ cargo install cloudiy
$ cloudiy share
Announcing resources: {Cpu: 16000, Memory: 65536, Gpu: 2, Vram: 49152}
Announcing capabilities: wgsl, docker, linux, x86_64, kernel:vector_add…
🚀 Node online — ID 9846…b1ec

The Node ID (an ed25519 key) is your address on the network — no port forwarding, no public IP (QUIC hole-punching via iroh). Your Solana keypair receives USDC payouts. Nodes are heterogeneous by design: GPU nodes, compute nodes, storage nodes, hybrids.

Consumers

Consumers declare workloads: what to run, which resources, which capabilities. Never a machine, never a driver:

$ cloudiy launch --to 9846…b1ec --image pytorch/pytorch --cap cuda --cap pytorch \
  --cpu 8 --memory-mb 32768 -- python app.py
🔏 Signature verified — result signed by the node you dialed
✅ Workload completed! · receipt x402 · logs returned

Or from an app / AI agent, via SDK (Rust · Python · JS):

# the whole integration, Python:
compute.run(cpu=8, memory=32, gpu_vram=24, template="ollama",
            command="ollama serve")

Workloads run in mandatory isolation (namespaces, cgroups, read-only fs, no host execution) and the environment is destroyed at the end — resources return to the pool automatically. Without payment the node answers Payment Required with its x402 USDC quote.
